# Таск-менеджер — план создания (v1)

Основа: `TASKS-SPEC-2.0.md` (решения владельца от 2026-11-26).
Принцип: каждый этап заканчивается живым замером; без замера этап не закрыт.

Компоненты: `bbx-tasks` (VPS, Node, схема `todo`), CLI `tasks` для агента,
экран «Задачи» в приложении (тот же стиль/дизайн, что чат и настройки),
локальные уведомления, доставка MAX/Telegram/email через роутер и `bbx mail`.

---

## Этап 0. Каркас и договорённости (0.5 дня)

1. Каталог `/opt/bbx-tasks` (src, dist, etc, test), package.json, tsconfig, esbuild.
2. `etc/tasks.env`: DSN (тот же Postgres), `TASKS_DEVICE_TOKEN`, `TASKS_SERVICE_TOKEN`,
   `TASKS_BIND=172.19.0.1`, `TASKS_PORT=8122`, `TASKS_TZ=Europe/Moscow`,
   `TASKS_QUIET=23:00-08:00`.
3. systemd `bbx-tasks.service` (User=bbx, Restart=always, только docker-сеть).
4. `ufw allow from 172.19.0.0/16 to any port 8122`.
5. `GET /healthz` (только локально) + `schema_migrations`.

**DoD:** сервис active, `/healthz` → `{"ok":true}`, порт снаружи закрыт.

## Этап 1. Схема `todo` и CRUD (1 день)

1. Миграции: `projects`, `tasks`, `tags`, `task_tags`, `attachments`, `reminders`,
   `agent_actions`, `audit`, `digests`, `pomodoro_sessions` — по спеке §4.
2. Ограничения: глубина подзадач 7, soft-delete (`deleted_at`), CHECK на статусы/приоритеты.
3. API: `GET/POST /api/v1/tasks`, `PATCH/DELETE /tasks/:id`, `/complete`, `/subtasks`;
   `GET/POST /projects`; фильтры `view=inbox|today|upcoming|kanban|project:<id>`.
4. Аутентификация: два Bearer-токена, сравнение за постоянное время; device vs service scope.
5. Аудит: каждая мутация → `todo.audit`; действия агента → `todo.agent_actions` + `reverse_payload`.

**DoD:** `curl` создаёт задачу, список её видит, `PATCH` меняет статус, в `audit` две записи;
подзадача глубже 7 отклоняется.

## Этап 2. CLI `tasks` для Масяни (0.5 дня)

1. `/opt/bbx-tasks/cli/tasks` + симлинк `/usr/local/bin/tasks` (как `bbx`).
2. Команды: `add`, `list`, `today`, `done`, `move`, `remind`, `undo`, `actions`, `digest`
   (последняя — заглушка до этапа 6), всё с `--json` и кодами возврата.
3. Навык `/root/.agents/skills/tasks/SKILL.md`: когда звать, как формулировать, лимиты,
   запрет на физическое удаление, обязательный `reason` для агента.

**DoD:** `tasks add "…" --due … --json` создаёт задачу; `tasks today --json` отдаёт её;
`tasks undo` отменяет последнее действие агента.

## Этап 3. Напоминания и уведомления (1.5 дня)

1. Планировщик в `bbx-tasks`: каждые 15 с `FOR UPDATE SKIP LOCKED` по `todo.reminders`.
2. Каналы:
   - `local` — API отдаёт due-напоминания устройству (`GET /api/v1/reminders/due`),
     приложение ставит AlarmManager/WorkManager-уведомление;
   - `max`/`telegram` — `INSERT bbx.outbound_msg` (channel/chat_id владельца), доставляет роутер;
   - `email` — `bbx mail` (metafeed), в том числе в тихие часы.
3. Тихие часы 23:00–08:00 МСК: local/max/telegram молчат, кроме priority=1 и due ≤ 2 ч;
   email — исключение, уходит всегда.
4. Snooze, backoff при ошибках, дедупликация `reminder_id+channel`, `attempts/last_error`.

**DoD:** напоминание на +2 мин приходит локально; ночное — не приходит (кроме срочного);
email уходит ночью; `todo.reminders` и `bbx.outbound_msg` содержат ожидаемые строки.

## Этап 4. Экран «Задачи» в приложении (2–3 дня)

Дизайн — в стиле приложения: `AssistantTheme`, `MaterialTheme.colorScheme`, скругления 16 dp,
карточки как в настройках, никаких сторонних библиотек UI.

1. Навигация: кнопка «Задачи» в боковом меню/настройках → экран (Compose, одна Activity).
2. Экран:
   - переключатель представления **Список / Канбан**;
   - табы Входящие / Сегодня / Предстоящее;
   - строка задачи: чекбокс, заголовок, проект, срок, приоритет (цвет как в теме);
   - канбан: 4 колонки **Надо / В работе / Ждёт / Готово**, drag-and-drop меняет `status`.
3. Карточка задачи: поля, подзадачи, напоминание, повтор, история агента, кнопка «Помодоро».
4. Сеть: `ApiClient` (OkHttp, тот же), токен в Keystore; pull-to-refresh; без офлайна.

**DoD:** задача, созданная голосом (через Масяню), видна в списке и на канбане; перетаскивание
меняет статус на сервере (проверяется `tasks list --json`); завершение свайпом сохраняется.

## Этап 5. Pomodoro (1 день)

1. Клиентский таймер (foreground hint), сервер хранит сессии `todo.pomodoro_sessions`.
2. Оверлей поверх экрана + полный экран настроек; каналы уведомлений.
3. Статистика: сегодня/неделя, по проектам.

**DoD:** таймер переживает сворачивание приложения; после завершения сессия видна в статистике.

## Этап 6. Агент-сценарии и дайджесты (1 день)

1. Масяня: «добавь/перенеси/напомни/что сегодня/отмени последнее» — через `tasks`.
2. Утренний дайджест 08:30, вечерний 21:30 — automation/таймер; шаблоны в `todo.digests`.
3. Автоперенос просрочек: раз в час, не более 20 задач за цикл, запись в `agent_actions`.
4. Лимиты агента: 60 изменений/мин, 500/час; при превышении — отказ с кодом.

**DoD:** «Масяня, напомни завтра в 9 позвонить» создаёт задачу и напоминание; «отмени» возвращает;
дайджест приходит в MAX; при 61-м изменении за минуту — отказ.

## Этап 7. Inbox (пайплайн/почта) (1 день)

1. `POST /api/v1/inbox` (service token) — приём кандидатов в задачи.
2. Правила «что считать задачей» — конфиг + решение агента; `source_ref` сохраняется.
3. Отображение во «Входящих», ручное подтверждение/удаление.

**DoD:** письмо/сообщение, помеченное агентом как задача, появляется во «Входящих» с ссылкой
на источник; удаление не трогает оригинал.

## Этап 8. Полировка (1 день)

1. Аудит-экран (последние действия, undo), метрики, лимиты.
2. Бэкап `todo` в существующий `bbx-gitpush`/ночной дамп; проверка восстановления.
3. `./check.sh` модуля: unit-тесты API/CLI + интеграционные на живой Postgres.

**DoD:** `check.sh` зелёный; бэкап проверен (restore в тестовую схему).

## Порядок и зависимости

```
0 каркас → 1 схема+CRUD → 2 CLI → 3 напоминания → 4 экран → 5 Pomodoro → 6 агент/дайджесты → 7 inbox → 8 полировка
```

Этап 4 (экран) можно вести параллельно с 3: API уже готов после 1–2.

## Риски

| Риск | Снятие |
|---|---|
| Android-сборка только в CI | пуш в ветку после каждого шага, маленькие коммиты |
| Локальные уведомления и батарея | AlarmManager для точных, WorkManager для гибких; не чаще 1 в минуту |
| Email через metafeed (чужой cron) | считать «доставлено» только по подтверждению; в логах — статус |
| Дубли напоминаний при рестарте | dedupe по `reminder_id+channel`, `SKIP LOCKED` |
| Стиль UI разъедется | только `AssistantTheme`/Material3 проекта, компоненты как в настройках |
